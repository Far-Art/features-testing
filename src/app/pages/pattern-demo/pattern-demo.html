imsPattern · מה שלא תואם לא נכנס

הדירקטיבה יושבת על input ו־textarea, מקבלת שם של פריסט, מחרוזת או RegExp, ובודקת מה הערך עומד להיות. הקשה שתשבור את התבנית מבוטלת ב־beforeinput, כך שהערך והמודל לעולם לא רואים אותה.

Built-in

שני פריסטים מובנים

integer ו־decimal מכסים את רוב השדות המספריים, ולצידם signedInteger ו־signedDecimal למי שצריך מינוס. אפשר לנקוב בשם הפריסט, או לקשור את הערך עצמו מתוך IMS_PATTERN — שתי הכתיבות מגיעות לאותה תבנית ולאותה התנהגות.

@for (card of numericPresets; track card.source) {

{{ card.title }}

{{ card.source }}

{{ card.hint }}

}

סכום שמגיע כאפס

imsPattern="decimal"

מיקוד בשדה בוחר את האפס כולו, כך שההקלדה מחליפה אותו במקום להיתקע אחריו. ערך המודל: {{ amount() }}

אותו פריסט, בלי תיקון

[imsPatternCorrect]="false"

אותה תבנית בדיוק, אבל בלי לכתוב לעולם: 0 ואז ספרה נחסם במקום להחליף את האפס.

Error popover

להסביר הקשה שנחסמה

הקשה שנחסמה לא משאירה זכר על המסך, ולכן ims-error-popover על אותו שדה מקבל הודעה בכל סירוב ומציג אותה פעם אחת: היא נשארת למשך זמן התצוגה של הפופאובר, ואינה חוזרת במעבר עכבר או במיקוד. פריסט מנסח את הסירוב לפי מה שהוקלד — אות אינה מקבלת את אותה הודעה כמו ספרה עשרונית שלישית — ושולח גם את הסיבה, כך שהניסוח בעברית נכתב פעם אחת ב־errorMapper הגלובלי. imsPatternMessage מחליף את כולן במשפט אחד, מספק משפט לתבנית משלכם, או מכבה אותו לגמרי.

חיווט אוטומטי

imsPattern="integer" ims-error-popover

נסו אות, נקודה ומינוס: ההקשה נחסמת כרגיל, וכל אחת מהן מקבלת הסבר משלה.

סכום עשרוני

imsPattern="decimal"

אות מקבלת הודעה על מספרים בלבד, נקודה שנייה מקבלת הודעה על נקודה עשרונית אחת, והספרה השלישית אחרי הנקודה מקבלת את מגבלת העשרוניות.

תבנית משלכם

imsPatternMessage="…"

תבנית שאינה פריסט שותקת עד שנותנים לה משפט — היא לא יודעת מה היא מתארת.

סירוב ושגיאת ולידציה יחד

required + imsPattern="integer"

מחקו את הערך ואז הקלידו נקודה: הסירוב מוצג מתחת לשגיאת החובה של הפקד, וכשחלון התצוגה שלו נסגר נשארת רק שגיאת הפקד.

סירוב שקט

[imsPatternMessage]="false"

הפריסט ממשיך לחסום, בלי להסביר. זו גם התנהגות ברירת המחדל בלי פופאובר על השדה.

String · RegExp

שתי דרכים להעביר תבנית

מחרוזת מתקמפלת ב־new RegExp() ללא דגלים; אובייקט RegExp שומר על הדגלים שלו, למעט g ו־y שמנוטרלים כי הם הופכים את test לתלוי־מצב.

מחרוזת סטטית

imsPattern="[0-9]*"

אין צורך בסוגריים מרובעים בתבנית מחייבת — הערך מעוגן ממילא.

אובייקט RegExp עם דגל i

/#?[0-9a-f]{0,6}/i

הדגל i מאפשר גם אותיות גדולות; כל תו מחוץ ל־hex נחסם.

textarea עם שורות חדשות

/[א-ת0-9 ,.\n-]*/

מעבר שורה מגיע כ־insertLineBreak, ולכן \n חייב להיות חלק מהתבנית.

Gotcha

התבנית חייבת לקבל קלט חלקי

הבדיקה רצה על הערך המלא בכל הקשה, ולכן תבנית שמתארת רק ערך גמור חוסמת את הדרך אליו.

לא עובד

[0-9]{3}

הספרה הראשונה כבר נדחית, כי 5 אינו שלוש ספרות.

עובד

[0-9]{0,3}

הטווח מקבל גם מצבי ביניים, והגבול העליון עוצר בשלוש.

Behaviour

מה הדירקטיבה מבטיחה

  • פריסט מוסיף התנהגות, לא חוזה חדש. integer ו־ decimal נבדקים כמו כל תבנית אחרת, ובנוסף מתקנים אפס מוביל ובוחרים ערך אפס בעת מיקוד.
  • סימן מינוס הוא פריסט נפרד. signedInteger ו־ signedDecimal מקבלים מינוס פותח, וגם מינוס לבדו בזמן ההקלדה, בעוד integer ו־decimal ממשיכים לחסום אותו. מינוס שני, או מינוס שאינו בתחילת הערך, נחסם.
  • שני תיקונים במקום סירוב. 0 שאחריו ספרה מאבד את האפס (01 → 1), ונקודה פותחת מקבלת אפס לפניה (. → 0.). התיקון חל על טקסט שנכנס, בהקלדה או בהדבקה — מחיקה לעולם לא מתוקנת, אחרת אי אפשר היה למחוק את האפס. imsPatternCorrect מחליף את התיקון בשלכם או מכבה אותו לגמרי.
  • עוגן מלא. התבנית נבדקת כ־^(?:…)$, בדיוק כמו התכונה pattern הטבעית.
  • מחיקה תמיד מותרת. גם ערך שהגיע מבחוץ ולא תואם אפשר לתקן — הדירקטיבה מחזירה לאחור רק הוספות.
  • הדבקה וגרירה באותו מסלול. insertFromPaste ו־ insertFromDrop נבדקים כמו הקלדה רגילה.
  • IME לא נשבר. טקסט חיבור שלא ניתן לביטול נבדק ב־ compositionend, ומוחזר לערך האחרון שהתקבל יחד עם מיקום הסמן.
  • המודל נשאר נקי. הקשה שנחסמה לא משנה את ה־DOM ולכן לא משדרת input — ngModel ו־formControl לא רואים אותה.
